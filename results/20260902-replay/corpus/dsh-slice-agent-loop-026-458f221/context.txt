## 门控放 driver，不放 render

## 写的时候撞出两个悬空 header

这两个我之前没看见，是把 header 常量搬过来时才发现的：

**一、OPEN FILES 的 header 承诺了一个不存在的列。**

```
# OPEN FILES (index — path · lines · CURRENT on-disk sha256 · read call. …
                                                    ^^^^^^^^^
```

而 `openFilesIndex` 早就不发 read call 了——[driver.ts:1216](src/driver.ts:1216) 的注释写明了原因（DSH 把读取工具注册为 `read` 且收 `{file_path}`，硬编码会随 host 改名而腐烂）。**header 没跟着改。** 已在提案里删掉该从句。

**二、`task_objective` 的 header 引用了我们要删的区。**

```
… (A newer retained user correction supersedes any conflicting detail)
```

指的是 `corrections` 区。而且原实现还有第二个分支（`objectiveStatus === 'provisionally_satisfied'` → `# PRIOR TASK BACKGROUND`），依赖一个无生产者的字段。两个都删，header 收成一句：

```
# STABLE TASK OBJECTIVE (original user objective; keep it active across follow-ups)
```

## pi 到底在说什么

pi（[@badlogicgames](https://jprokay.com/post/018-pi-coding-agent) 做的）只有 4 个工具，刻意不做 subagent、不做 plan mode、连权限系统都没有（作者原话是默认"living dangerously"）。核心是 CLI-first：一切先做成命令行工具，扩展只负责渲染它的输出。

**但注意它省的是什么：工具面。** "bash is all you need" 是在说别给模型 50 个专用工具，给它 bash 让它自己组合。

## Vercel 自己做的验证很值得看

[Testing if "bash is all you need"](https://vercel.com/blog/testing-if-bash-is-all-you-need) 拿 GitHub issues 数据集比了三种：

| | SQL | Bash | Filesystem |
|---|---|---|---|
| 准确率 | **100%** | 52.7% | 63.0% |
| token | 155K | 1,062K | 1,276K |
| 成本 | $0.51 | $3.34 | $3.89 |

bash 臂 **7 倍 token、6.5 倍成本、9 倍耗时，准确率一半**。而他们点名的首要失败原因是：**"lacked schema context about JSON file structure"** —— 缺 schema。

所以这条哲学有它的边界：**工具面越薄越好，但结构化的东西给模型一个 schema 是赚的。** tape 的 hash 信任规则、OPEN FILES 的盘态索引，正是结构化的东西。

## 但你还是对的，理由不一样

不是"schema 本身多余"，是**我那个 `Region` 表不承重**。

私有模块、固定 4 个区、不动态注册、除了渲染没有第二种遍历。那 `Region` 接口 + `zone` 字段 + 排序 + 表，全部可以塌成**四个函数调用，按顺序**：

```ts
interface SliceCtx {
  request: string
  goal: string
  tape: readonly TapeEntry[]
  openFiles: string      // driver 现渲染（I/O + hash 都在它那边）
  lastError: string
}

export function assemble(ctx: SliceCtx, systemPrefix: string, hints = ''): [string, string] {
  const body = [
    ctx.tape.length ? TAPE_HDR + ctx.tape.map(e => e.rendered).join('') + '\n' : '',
    ctx.goal.trim() && ctx.goal.trim() !== ctx.request.trim() ? OBJ_HDR + ctx.goal + '\n\n' : '',
    ctx.openFiles ? FILES_HDR + ctx.openFiles + '\n\n' : '',
    ctx.lastError.trim() ? ERR_HDR + ctx.lastError + '\n\n' : '',
  ].filter(Boolean).join('\n')

  return [systemPrefix,
    (body ? `<context>\n${body}\n</context>\n\n` : '')
    + (ctx.request.trim() ? REQ_HDR + ctx.request + '\n\n' : '')
    + NOW_FOOTER + (hints ? `\n${hints}` : '')]
}
```

**这就是全部。** 一个接口、一个函数、五个 header 常量。

- `zone` → 数组顺序
- `name` → 就是那一行在读什么
- 区表 → 数组字面量
- 加一个区 → 加一行

一样都没少。而且我上一版还把 `openFiles` 从字符串改成了结构化 union —— 那是我把它**改复杂了**，改回字符串，driver 本来就是这么产的，零迁移。
